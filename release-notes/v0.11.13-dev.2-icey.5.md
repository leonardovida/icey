## Highlights

- **More reliable fullscreen detection on every macOS version.** Icey misread which spaces are fullscreen, which affected the menu bar styling, show on hover and click, and the Ice Bar ([#27](https://github.com/leonardovida/icey/pull/27)).
- **Fewer hangs and crashes.** Applying item spacing can no longer hang. Odd values in a settings file no longer crash Icey at launch ([#27](https://github.com/leonardovida/icey/pull/27)).
- **100 more upstream items reviewed.** Every open Ice pull request and 64 more Ice issues are checked, and the useful fixes from the pull requests are included with credit ([#27](https://github.com/leonardovida/icey/pull/27)).

## Features

- **Fade the Ice Bar in and out:** turn on Settings > General > Use Ice Bar > **Fade in and out** for a short fade when the Ice Bar opens and closes. It's off by default. Adapted from [jordanbaird/Ice#1002](https://github.com/jordanbaird/Ice/pull/1002) by gmkrxb ([#27](https://github.com/leonardovida/icey/pull/27)).

## Bug Fixes

Each fix says what went wrong before, and what happens now.

- **Fullscreen detection:**
  - Before: Icey read the type of each space wrongly, so a system space counted as fullscreen, and whether a real fullscreen space counted depended on how Icey was compiled.
  - Now: Icey reads the space type macOS reports, so only fullscreen spaces count. The menu bar styling, show on hover and click in fullscreen, and the Ice Bar all rely on this. From [jordanbaird/Ice#980](https://github.com/jordanbaird/Ice/pull/980) by PWB97.
- **Crash at launch from a settings value:**
  - Before: a hotkey with an out-of-range key code, for example in an imported settings file, crashed Icey every time it started. A color with too few components could be misread.
  - Now: Icey ignores such values when it reads its settings. From [jordanbaird/Ice#985](https://github.com/jordanbaird/Ice/pull/985) by godlockin.
- **Menu Bar Item Spacing hanging on Apply:**
  - Before: if an app survived being force-quit, Apply waited forever. An app could also fail to relaunch because its old copy was still listed as running.
  - Now: Icey stops waiting a second after the force-quit and reports the app as not restarted. It relaunches every app that quit. From [jordanbaird/Ice#923](https://github.com/jordanbaird/Ice/pull/923) by heyalchang.
- **Icey's own items not recognized on macOS 26:**
  - Before: when macOS 26 couldn't tell which app owned an item, Icey failed to recognize its own dividers and kept rebuilding its item list. The helper that asks macOS about items could also lose its connection mid-request.
  - Now: Icey recognizes its dividers by name, and the helper reconnects on the next request. From [jordanbaird/Ice#911](https://github.com/jordanbaird/Ice/pull/911) by tducp015 and [#963](https://github.com/jordanbaird/Ice/pull/963) by lxy1992.
- **A shortcut blocking typing:**
  - Before: a shortcut saved for the always-hidden section stayed active while that section was turned off. Option-A, for example, stopped typing "å" in every app.
  - Now: the shortcut only works while the always-hidden section is on ([jordanbaird/Ice#498](https://github.com/jordanbaird/Ice/issues/498)).

These fixes weren't tested on every affected setup. Please [report](https://github.com/leonardovida/icey/issues/new/choose) anything that still happens.

## Highlights

- **Icey does less work when you aren't using it.** Closed windows no longer redraw, timers stop while their output is hidden, and drags elsewhere on your Mac no longer reach Icey ([#37](https://github.com/leonardovida/icey/pull/37), [#38](https://github.com/leonardovida/icey/pull/38), [#40](https://github.com/leonardovida/icey/pull/40)).
- **Fewer calls to the window server and to other apps.** Checks Icey runs every few seconds or on every click now ask macOS once instead of once per window or app ([#39](https://github.com/leonardovida/icey/pull/39), [#41](https://github.com/leonardovida/icey/pull/41), [#43](https://github.com/leonardovida/icey/pull/43)).
- **A much smaller settings file.** The menu bar appearance setting shrinks from about 63 KB to under 1 KB if you use the default colors ([#42](https://github.com/leonardovida/icey/pull/42)).

## Upgrading from 0.12.0

Nothing to do. Your settings, item layout, hotkeys and permissions stay as they are.

1. Wait for Icey to offer the update, or choose Settings > About > **Check for Updates**.
2. Install it, and Icey restarts on its own.

## Bug Fixes

### Speed, energy and memory

- **Closed windows stop redrawing:**
  - Before: Settings, Permissions and the Menu Bar Appearance editor stayed in memory while closed. They redrew on every change to Icey's state, including each time the Ice Bar opened.
  - Now: their content is built only while the window is open, and released a second after it closes. Each pane opens at the top of its page ([#37](https://github.com/leonardovida/icey/pull/37)).
- **Fewer wakeups while idle:**
  - Timers for the Ice Bar colors, item images and the Settings preview now run only while those are on screen.
  - The item list refresh no longer wakes Icey twice every 5 seconds.
  - Updates that don't change anything no longer redraw the views that show them ([#38](https://github.com/leonardovida/icey/pull/38)).
- **Drags reach Icey only while Command is held:**
  - Before: with "Show all sections when dragging" or a menu bar shape on, every drag on your Mac reached Icey, up to 120 times a second. This included selecting text and moving windows.
  - Now: Icey listens for drags only while Command is held, which macOS needs to move menu bar items anyway ([#40](https://github.com/leonardovida/icey/pull/40)).
- **Faster checks on clicks and scrolling:**
  - Icey finds which menu bar items are on the current space with one call to macOS instead of one per item. Before, this was the only work Icey did on the main thread while idle.
  - Each click in the menu bar reuses one window list.
  - The screen's usable area is read only when a check needs it ([#39](https://github.com/leonardovida/icey/pull/39), [#40](https://github.com/leonardovida/icey/pull/40)).
- **Menu bar shapes on several displays:** one timer updates the wallpaper and app menus for every display instead of two timers per display. The border reuses the shape it outlines ([#41](https://github.com/leonardovida/icey/pull/41)).
- **Smaller appearance setting:**
  - Each color used to store a full color profile, so twelve default colors took about 63 KB, nearly all of Icey's settings file.
  - Colors that match the defaults are now left out. Older Icey and Ice versions still read the same appearance ([#42](https://github.com/leonardovida/icey/pull/42)).
- **Fewer questions to other apps (macOS 26 and later):** while Icey's helper can't find which app owns a menu bar item, it remembers for 30 seconds which apps have no menu bar items. It no longer asks every app again on each refresh ([#43](https://github.com/leonardovida/icey/pull/43)).

### Other fixes

- **Hotkey left off after closing Settings:**
  - Before: closing Settings or switching panes while recording a hotkey left the recording running in the background, and the hotkey stayed off.
  - Now: closing the window or switching panes cancels the recording, and your previous hotkey works again ([#37](https://github.com/leonardovida/icey/pull/37)).

## Compatibility

- **Settings opens a moment later from the Ice Bar or search:** the window now builds its content when it opens, about a tenth of a second more. Opening it from the Icey menu is almost unchanged.
